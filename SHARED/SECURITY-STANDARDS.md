# Security Standards and Control References

Use the current official edition at assessment time. Record the edition, retrieval date and URL in each report. Do not assume standards are exhaustive or claim conformance without mapping controls and evidence.

## Application security
- OWASP Top 10 — web application risk awareness.
- OWASP ASVS — verifiable application security requirements and control catalogue.
- OWASP API Security Top 10 — API-specific risk categories.
- OWASP Cheat Sheet Series — implementation guidance for individual controls.

## Mobile security
- OWASP MASVS — mobile application security verification requirements.
- OWASP MASTG — mobile application security testing guide.
- OWASP MASWE — mobile application weakness enumeration.

## Weakness, exploit and scoring taxonomies
- CWE — Common Weakness Enumeration for root-cause classification.
- CAPEC — Common Attack Pattern Enumeration and Classification.
- CVSS v4.0 — severity scoring context; supplement with business impact and exposure.

## Secure development and infrastructure
- NIST SSDF (SP 800-218) — secure software development practices.
- NIST Cybersecurity Framework — cybersecurity risk governance and outcomes.
- CIS Benchmarks — configuration hardening guidance where applicable.
- Vendor-specific secure configuration and hardening documentation.

## Vulnerability intelligence sources
- Vendor security advisories and release notes are primary for affected/fixed version interpretation.
- CISA Known Exploited Vulnerabilities catalog for known exploited issues.
- NVD/CVE records for public vulnerability identifiers and references.
- OSV for ecosystem/package vulnerability matching.
- GitHub Security Advisories for package ecosystem advisories.
- Relevant language, framework, CMS, plugin, cloud and operating-system advisory feeds.

## Mapping requirement
For each major control domain, record: applicable standard/control, project-specific implementation, evidence, test method, result and limitation. A blank or untested control is not passed. An OWASP category or checklist is not a substitute for architecture-specific threat modeling, manual review and testing.
